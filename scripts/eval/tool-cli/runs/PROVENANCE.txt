Which freeze graded these runs
==============================

The two run directories here were produced under the ORIGINAL commit A, whose
grade.py digest was 1e58699b4cdf1333692b0f23515e73b4f89e3d49925ad3d52cbeef66ce082440.

The #3412 primary review (t-20260828143201047260-31254-76) proved two fail-open
paths in that grader: the mixing gate reported "0 of 45" for a control that
contributed zero runs, and an unreadable `arm` blinded mixing detection outright.
Answering the follow-up question about re-run scope surfaced a third: a matrix
that lost a single confirmation pair recomputed its interval off-table at N=59
and still read PASS, though SPEC.txt:167 pins the gate to a lookup AT N=60.

A second independent review then found three more runs the grader counted that
it should have refused: a model that was never resolved (or resolved off the
frozen pin), a control run carrying an arm its scenario never declared, and two
runs claiming one (scenario, pair, arm) cell, where the later one silently
replaced the earlier.

A third round of review found that every gate so far counted what was on disk
without establishing that what was on disk IS the frozen experiment: SPEC-required
metadata fields went unread, the model was compared metadata-to-metadata instead
of against the stream's own init event, an unreadable scenario declaration meant
"no constraint" (and a non-object one crashed the aggregate), nothing compared the
runs to SPEC section 6's 210-cell plan, matrix.sh took its plan from the
environment, and resume skipped any directory holding a metadata.json without
reading it. The summary therefore gained a `plan_gate`, which means a new run's
summary.json is not key-comparable to the two below.

Fixing all of it changed frozen files, so grade.py is now
65d944972855f5b960a98ef2d8c9f12167c282bbf76aa1587d051e8e439dcb37 and matrix.sh is
a5d70a792bd08af30818971b88f89e49c3678b4a68c8456c049d7f97913ad21e; this harness is a NEW commit A'.

SPEC.txt section 6 is explicit about what that means: "No prompt/grader/table
edits after commit A — if one is needed, the matrix restarts from zero under a
new commit A'." These results therefore do NOT carry forward as results under the
current freeze. They stand as the record of what was run under the old one.

Measured, not assumed: re-grading the surviving E2 raw tree with the FIXED grader
reproduces runs/E2-20260828T090026Z/summary.json in every value it already had —
the only difference is the `plan_gate` key the third round added, which PASSES on
that tree (210 cells, none missing, none unexpected, none duplicated, and its
manifest's plan equal to the frozen one in order). report.py is deliberately
unchanged, so the two reports below still re-render byte for byte from the
summaries they were made from; the plan gate lives in summary.json only, and
putting it in the renderer would break exactly that property. So the fixes are
result-invariant on the data that still exists — evidence about what a re-run
would be expected to show, not a substitute for the re-run SPEC section 6
requires. E1 (20260828T063955Z) cannot be re-graded at all: its raw run tree was
in a worktree that has since been released.

SPEC section 6 now also bounds what a restart authorizes: EXACTLY ONE fresh
210-run matrix, only after the new A' carries dual independent VERIFIED reviews,
and those verdicts cover that one matrix rather than licensing retries until one
passes. That clause is itself frozen, so moving it forces another A'.

Phase 1 remains excluded either way (SPEC.txt:169).
